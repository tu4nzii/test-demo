# 轴先验提取与图表分类的补充说明

## 总体回应

我们同意审稿人的核心担忧：当前轴先验提取模块依赖较强的图表结构假设，不能被描述为对任意真实世界图表都稳定成立的步骤。修订稿中应将该模块明确定位为“可验证、可失败、可降级”的弱先验提取器，而不是端到端流程的不可缺少前提。我们已经补充独立评估脚本，在 `backend/charts` 上统计分类准确率、轴/刻度提取失败率和参数敏感性。

复现实验文件：

- 评估脚本：`backend/evaluation/scripts/evaluate_axis_prior_reviewer_questions.py`
- 评估结果：`backend/evaluation/results/axis_prior_reviewer_eval.json`
- 运行命令：`python backend\evaluation\scripts\evaluate_axis_prior_reviewer_questions.py --output backend\evaluation\results\axis_prior_reviewer_eval.json`

若需要把 MLLM 刻度文本/轴类型识别也纳入同一个评估文件，可运行：

`python backend\evaluation\scripts\evaluate_axis_prior_reviewer_questions.py --include-mllm --cache-only --mllm-limit 20 --output backend\evaluation\results\axis_prior_reviewer_eval_with_mllm.json`

去掉 `--cache-only` 时才会为缺失样本调用 MLLM；缓存 key 已绑定数据集、图像内容、提示词签名、模型和 temperature。

## 图表类型分类

图表类型分类只用于选择候选轴先验提取程序：Cartesian 图表（line、scatter、bubble、v_bar、h_bar）进入直线轴和刻度线流程；polar 图表（radar、rose）进入圆心、半径和径向刻度流程；pie、donut 等无坐标轴图表不执行轴先验提取。

为避免循环论证，修订稿中应明确：图表分类不应由最终被评估的同一个 MLLM 决定。当前工程中的 `type_detection/chart_type.py` 使用 MLLM 分类，这在论文评估中确实会引入审稿人指出的风险。我们建议在实验中改为使用独立分类器或人工标注的图表类型元数据。为量化该步骤，我们在 `backend/charts` 的 916 张有标注图表上训练并交叉验证了一个独立的传统 CV 特征 + Random Forest 分类器，仅使用低层图像特征，不使用下游 MLLM 输出。

5 折交叉验证结果如下：

| 类别 | 召回率 |
| --- | ---: |
| bubble | 100.00% |
| donut | 100.00% |
| h_bar | 97.83% |
| line | 99.63% |
| pie | 100.00% |
| radar | 100.00% |
| rose | 100.00% |
| scatter | 98.99% |
| v_bar | 100.00% |

总体准确率为 99.56%（912/916），错误样例为 4 张：`h_bar_006.png`、`h_bar_129.png`、`line_260.png`、`scatter_095.png`。错误分类会影响候选先验程序的选择，因此实现中不应直接信任分类结果，而应把分类器输出作为候选路径，并用几何验证决定是否接受先验。如果验证失败，则丢弃该先验并进入无先验或部分先验模式。

## Cartesian 轴提取

当前实现使用固定参数，而不是逐图调参：

| 步骤 | 参数 |
| --- | --- |
| 灰度化 | OpenCV BGR-to-gray |
| Canny | threshold1 = 50, threshold2 = 150 |
| Probabilistic Hough | rho = 1, theta = 1 degree, threshold = 20, minLineLength = 20, maxLineGap = 20 |
| 轴方向过滤 | 与水平/垂直方向夹角不超过 10 degrees |
| 主轴候选长度 | 至少为图像宽或高的 35% |
| 刻度扫描 | scan_range = 10 px, min_tick_height = 3 px, dark_threshold = 230 |

在 715 张 Cartesian 图表上，默认参数下能同时返回 X/Y 两条主轴的比例为 669/715 = 93.57%，失败率为 6.43%。分类型结果：

| 类别 | 样本数 | 两轴返回率 | 失败率 |
| --- | ---: | ---: | ---: |
| line | 273 | 100.00% | 0.00% |
| scatter | 99 | 79.80% | 20.20% |
| bubble | 100 | 84.00% | 16.00% |
| v_bar | 151 | 99.34% | 0.66% |
| h_bar | 92 | 90.22% | 9.78% |
| ALL | 715 | 93.57% | 6.43% |

刻度线检测比轴线检测更脆弱。在两轴成功返回的样本中，平均像素级刻度召回率为 X 轴 82.35%、Y 轴 59.04%。这说明 CV 轴定位可作为弱几何先验，但刻度线像素扫描不应作为唯一信息来源，尤其在淡色轴线、无刻度线、设计工具风格化图表中更容易失效。

## Canny 参数敏感性

我们测试了四组 Canny 阈值，其余参数固定：

| Canny 阈值 | 两轴返回率 | 失败率 | X 刻度召回 | Y 刻度召回 |
| --- | ---: | ---: | ---: | ---: |
| 30/90 | 93.57% | 6.43% | 82.37% | 59.10% |
| 50/150 | 93.57% | 6.43% | 82.35% | 59.04% |
| 80/200 | 93.71% | 6.29% | 82.29% | 59.21% |
| 100/250 | 93.29% | 6.71% | 82.50% | 59.28% |

在当前合成图表集上，直线轴返回率对 Canny 阈值不敏感。但这并不意味着整体轴先验稳健：失败主要来自视觉上不占主导的坐标轴、短轴线、与数据标记/网格线混淆、以及刻度线样式变化。

## Polar 轴提取

当前 polar 模块也使用固定参数：

| 步骤 | 参数 |
| --- | --- |
| GaussianBlur | kernel = 9x9, sigma = 2 |
| HoughCircles | dp = 1.2, minDist = 100, param1 = 20, param2 = 30 |
| radar 半径范围 | height/5 到 height/4 |
| rose 半径范围 | height/4 到 height |

在 99 张 polar 图表（radar 50、rose 49）上，默认参数下 HoughCircles 至少返回一个圆候选的比例为 99/99 = 100%。圆心误差中位数为 2.24 px；第一候选半径误差中位数为 2 px；若从全部候选中选择与标注半径最接近的圆，半径误差中位数为 1 px。

HoughCircles 的 `param2` 更敏感：

| param2 | 圆候选返回率 | 失败率 | 平均候选数 |
| --- | ---: | ---: | ---: |
| 20 | 100.00% | 0.00% | 50.83 |
| 30 | 100.00% | 0.00% | 26.87 |
| 40 | 97.98% | 2.02% | 5.60 |
| 50 | 76.77% | 23.23% | 2.21 |

因此，修订实现不应将“第一组圆”直接作为最终先验，而应枚举候选圆，并通过同心性、中心一致性、半径序列一致性和径向刻度标签对应关系进行验证。没有同心圆环或没有径向数字刻度标签时，不应填充伪造的径向数值映射。

## 失败检测与备用机制

修订稿应加入显式的先验状态：`axis_prior_status = full | partial | none`。仅通过几何验证的部分进入下游提示，失败部分不用于约束 MLLM。

1. 如果只有一个坐标轴存在：
   接受单轴先验，但仅在该方向生成或约束网格；另一方向不做几何插值。输出 `partial`，并由 OCR/MLLM 直接读取另一方向的数据区域。

2. 如果坐标轴没有视觉上占主导的轴线：
   不强制选择最长线。先尝试用 OCR 到的刻度标签边界框拟合水平/垂直基线；如果标签也不足，则输出 `none`，进入无先验模式。

3. 如果没有刻度线：
   不执行像素级刻度扫描匹配。若存在至少两个刻度标签，则用标签位置拟合像素-数值映射；若标签少于两个，则不生成数值网格，只保留图表类型、颜色和数据区域等非轴先验。

4. 如果 polar 图中没有同心圆环：
   不强制用 HoughCircles 产生半径先验。可用扇区/数据点/多边形外包络估计中心和最大半径，但半径数值尺度必须由径向标签或明确标注确认；否则仅输出中心或角度先验。

5. 如果没有与径向参考圆对应的数字刻度标签：
   只保留圆心和角度方向信息，不把像素半径映射成数值半径。向下游 MLLM 明确提示“无径向数值先验”，避免生成不存在的刻度。

## 验证逻辑

先验接受条件应包括：

- Cartesian：X/Y 轴候选需接近水平/垂直、长度足够、交点位于图表绘图区附近；刻度像素需沿轴单调排列；若使用标签拟合，至少需要两个可读标签。
- Polar：圆候选需共享近似圆心；半径候选需形成合理递增序列；径向数值标签需与候选圆位置一致；没有标签时不得建立数值半径映射。
- 分类输出只决定候选流程，不决定最终先验是否有效。候选流程未通过验证时，先验被丢弃。

这样处理后，轴先验从“强前提”变为“可选的、带置信状态的辅助信息”。当视觉结构假设不满足时，系统不会中断，也不会向下游传递错误坐标约束，而是退化为无先验或部分先验的 MLLM/OCR 读取流程。
