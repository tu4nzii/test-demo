# 轴先验提取与图表分类补充说明

## 对审稿意见的直接回应

我们同意审稿人的判断：当前轴先验提取模块依赖较强的视觉结构假设，不能被描述为对任意真实世界图表都稳定成立的步骤。修订稿中应将其定位为一个可验证、可失败、可降级的先验模块，而不是不可或缺的端到端前提。

## 图表类型分类

流程开始时的图表类型分类用于选择不同的轴先验提取程序：

- 笛卡尔图表：line、scatter、bubble、vertical bar、horizontal bar 进入直线轴与刻度线提取流程。
- 极坐标图表：radar、rose 进入圆心、半径、径向刻度提取流程。
- pie、donut 等无坐标轴图表不执行轴先验提取。

为避免循环论证，修订稿中应明确：图表类型分类不由最终被评估的 MLLM 完成，而应由一个独立分类器或人工标注的图表类型元数据完成。我们在 `backend/charts` 上用一个独立的传统 CV 特征 + Random Forest 分类器做了 5 折交叉验证，只使用图像低层特征，不使用下游 MLLM 输出。结果如下：

- 样本数：916。
- 总体分类准确率：99.78%。
- 每类召回率：bubble 100%、donut 100%、h_bar 100%、line 100%、pie 98.04%、radar 100%、rose 97.96%、scatter 100%、v_bar 100%。

错误分类的影响是可控但不可忽略的：若把笛卡尔图误分为极坐标图，直线轴先验会完全缺失；若把 radar/rose 误分为笛卡尔图，会产生无意义的 X/Y 轴。因此实现中应加入验证逻辑：分类器只决定候选流程，最终是否接受该先验由几何一致性检查决定。若候选流程未通过验证，则丢弃先验并进入无先验降级模式。

## 笛卡尔轴先验提取细节

当前实现使用固定参数：

- 灰度化输入图像。
- Canny 边缘检测：threshold1 = 50，threshold2 = 150。
- Probabilistic Hough Transform：rho = 1，theta = 1 degree，threshold = 20，minLineLength = 20，maxLineGap = 20。
- 只保留接近水平或垂直的线段，角度容忍度为 10 degrees。
- 候选轴线长度需超过图像宽度或高度的 50%。
- X 轴选择最靠下的长水平线，Y 轴选择最靠左的长垂直线。
- 刻度线通过沿轴线附近固定窗口扫描暗色像素获得，scan_range = 10，min_tick_height = 3，灰度阈值约为 200。

在 `backend/charts` 的 715 张笛卡尔图表上，当前启发式轴检测能够返回两条主轴的比例为 93.57%，即失败率为 6.43%。分类型结果：

- line：273/273，100.00%。
- scatter：79/99，79.80%。
- bubble：84/100，84.00%。
- v_bar：150/151，99.34%。
- h_bar：83/92，90.22%。

但刻度线检测比轴线检测脆弱得多。平均刻度召回率约为 X 轴 63.19%、Y 轴 55.51%。这说明当前 CV 轴线定位可作为弱先验，但不能把刻度线扫描作为唯一信息来源。

## 参数敏感性

在 Canny 参数上，我们测试了四组阈值：

- 30/90：轴线返回率 93.57%。
- 50/150：轴线返回率 93.57%。
- 80/200：轴线返回率 93.71%。
- 100/250：轴线返回率 93.29%。

因此，在当前合成图表集上，直线轴是否能被返回对 Canny 阈值不敏感。但这不代表刻度线检测同样稳定；刻度线依赖像素级暗色短线扫描，对样式变化、淡色坐标轴、无刻度线设计更加敏感。

极坐标模块当前参数：

- GaussianBlur kernel = 9x9，sigma = 2。
- HoughCircles：dp = 1.2，minDist = 100，param1 = 20，param2 = 30。
- radar 半径范围：height/5 到 height/4。
- rose 半径范围：height/4 到 height。

在 99 张 polar 图上，HoughCircles 均能返回圆，但存在半径选择问题：

- radar：50/50 返回圆心，中心误差中位数约 3 px，但半径误差中位数约 108.5 px，说明当前范围常选到非目标环。
- rose：49/49 通过，中心误差中位数约 1.41 px，半径误差中位数约 1 px。

参数敏感性显示，提高 HoughCircles 的 param2 会降低返回率，但可减少错误半径候选；因此修订实现不应使用“第一组圆”作为最终圆环，而应枚举候选圆并按同心性、半径序列一致性、刻度标签对应关系选择。

## 明确的失败检测与备用机制

修订稿中建议加入如下验证与降级逻辑。

1. 如果只有一个坐标轴存在：
   - 接受单轴先验，但只在该轴方向生成或约束网格。
   - 另一方向不做几何插值，改由 MLLM 或 OCR 直接读取数据区域。
   - 输出中标记 `axis_prior_status = partial`。

2. 如果坐标轴没有视觉上占主导的轴线：
   - 不强行寻找最长线。
   - 使用刻度标签/OCR 边界框拟合轴方向，例如通过数字标签中心点拟合水平或垂直基线。
   - 若标签也不足，则进入无先验模式。

3. 如果没有刻度线：
   - 不执行像素扫描刻度线匹配。
   - 使用刻度标签文本位置拟合像素-数值映射。
   - 若标签不足两个，则不生成数值网格，只保留图表类型和颜色等非轴先验。

4. 如果极坐标图没有同心圆环：
   - 使用扇区/数据点/多边形外包络估计中心。
   - 半径尺度不由圆环决定，改由径向标签或数据标记的最大半径估计。
   - 若中心或尺度置信度不足，则不生成极坐标网格。

5. 如果没有与径向参考圆对应的数字刻度标签：
   - 仅保留中心和角度轴先验。
   - 不把像素半径映射为数值半径。
   - 对最终 MLLM 提供“无径向数值先验”的提示，而不是填入伪刻度。
